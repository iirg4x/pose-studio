# Pose Studio interface design system

The canonical design contract is [docs/UI_RULEBOOK.md](../docs/UI_RULEBOOK.md). Read it before changing UI, CSS, interaction, responsive layout or animation of interface elements. The [interactive visual reference](../docs/ui-rulebook.html) illustrates the same contract.

Approved direction: full-screen 3D canvas; contextual A ribbon near the selected controller; enabled/open-by-default complete control inspector with a persistent toolbar toggle; C timeline arrangement with one shared dark surface root. Quick, menu, dialog and touch/floating panel backgrounds use `rgb(18 29 40 / 70%)` (30% transparency). Fine-pointer desktop uses an opaque `--surface-dock` Properties column plus timeline/transport dock rows that reserve scene space; touch/coarse docking remains contextual and full-screen. Inner timeline bands use only an 8% tint over their single root surface; Transform follows the same flat inspector-section treatment without a separate inset shell. Control-properties content remains opaque. Import lives inside the Pose menu only, with no persistent Import button. Settings and compact Workspace/Panels access may remain at the top right as Pose-specific placement rules, not universal desktop standards. The latest direct live feedback supersedes the original 70% transparency choice; the latest written rule book supersedes incidental generated-image details.

Key tokens: 4px spacing base; every visible outer control, joined shell, floating panel, menu, popover, dialog and badge uses one `--radius-shared: 8px`; joined internal edges and viewport edges use `--radius-flush: 0px`. The approved Tablet Reference Control properties styling and colors apply to every panel; the current implementation is not the visual authority. Shared surfaces are `--inset: #1b2835`, `--panel: #192735`, `--raised: #223140`, `--hover: #2d4153`, `--pressed: #365064`, `--selection: #243e49`, `--text: #e3e9f1`, `--border: #3a4d60`, and `--border-subtle: color-mix(in srgb, #3a4d60 45%, transparent)`. The action accent is `#42d8e9`. Surface tokens are `--surface-quick: rgb(18 29 40 / 70%)`, `--surface-menu: rgb(18 29 40 / 70%)`, `--surface-timeline: rgb(18 29 40 / 70%)`, `--surface-ruler: rgb(18 29 40 / 70%)`, and `--surface-dock: var(--panel)`. Dialogs share `--surface-menu` and the same shared outer radius while retaining focus behavior. Joined hover/selection fills the cell, clipped by the outer shell; list-row selection uses the dark `--selection` surface with readable `--text` and a cyan check or inset edge. Use one layer selector and one transport. Quick controller tools hide during manipulation/playback. Detailed inspectors remain available for live feedback. Set alpha on backgrounds rather than containers: floating/touch quick ribbon, inspector, menus, tablet panels, dialogs, timeline, transport and ruler use the shared 70% background alpha (30% transparency), while fine-pointer desktop dock roots use opaque `--surface-dock`; inner timeline bands use only an 8% tint over their single root; control-properties content, fields, labels, text, icons, curves, handles, keyframes and timeline marks stay fully opaque. Verify contrast against the composited scene where transparency is used without imposing a separate minimum-alpha gate.

Avoid panel overlap where possible. If a floating menu or panel must overlap another surface, only the scene may show through its transparent background; within the covered lower region, underlying panel text, controls and panel background must be masked, with no stacked text or competing controls. Mask only that covered region; do not replace the transparent top panel with an opaque top surface. Keep the obscured surface mounted and restore it when the upper surface is dismissed rather than closing or resetting it because it is covered. Active-layer/menu list rows use dark `--selection` with readable `--text` and a cyan check or inset edge; joined mode buttons keep their cyan selected cells.

Control properties is enabled and open by default when a selection can populate it. Its toolbar toggle is a persistent open/closed preference across deselection and reselection: no selection hides the contextual panel without resetting the preference, and a later selection restores it when enabled. Keys and Curves share the same outer editor size and preserve resize state; touch/coarse input shows one editor at a time. Measure curve/effect geometry from committed editor bounds before first paint, then observe later size changes without a visible fallback correction.

Approved visual references: `../../work/ui-layout-concepts/a-portrait-tablet.png` and `../../work/ui-layout-concepts/dynamic-a-properties.png`. They define the Control properties panel treatment and colors; they do not verify the current implementation or physical-device/browser behavior.

Keep the rule book and visual reference synchronized. These are target requirements; do not describe the existing app as compliant or claim physical iPhone/browser verification from this documentation.
