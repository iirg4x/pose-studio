Pose Studio UI rule book

The rulebook makes the editor feel like one instrument: predictable geometry, restrained surfaces, strong focus, and controls that appear when they are useful. The Tablet Reference Control properties treatment is the shared visual language for every panel.

00 · Approved reference

Tablet Control properties set the panel language

Every panel follows the approved Tablet Reference styling and colors. These images are the design reference; current implementation styling and screenshots do not override the shared contract.

Reference rule: Import is inside the Pose menu and has no persistent button. Settings and compact Workspace/Panels access may remain at the top right. Touch docking remains full-screen and contextual. On fine-pointer desktop, the Properties dock stays mounted when no controller is selected; its open/collapsed preference alone sets the dock size, and selection changes do not open, close or resize it. When open with no selection, it shows the existing Animation properties plus small Select all and Box select actions. Selecting returns to selected-control context unless Animation context was deliberately chosen; a collapsed no-selection dock keeps its restore handle reachable. Desktop rail tools show visible captions beneath their icons; longer captions wrap, and overflowing tools scroll within the dock.

01 · Foundation

Surfaces and ink

Use the shared Tablet Reference palette across every panel. Quick, menu, dialog, timeline, transport and ruler backgrounds use the dark 70% alpha surface, leaving 30% transparency; inner timeline bands and the Transform inset use an 8% tint. Control properties content, text, fields, labels, icons and data marks stay fully opaque. Verify contrast against the composited scene.

Surface decision: Latest direct live feedback supersedes the original 70% transparency choice; shared roots use the dark 70% alpha surface with opaque Control properties content.
Overlap rule: Avoid overlapping panels where possible. If a floating menu or panel must overlap another surface, only the scene may show through; within the covered lower region, underlying panel text, controls and panel background stay masked with no stacked text. Mask only that covered region; keep the top surface transparent and restore the obscured surface when the top surface is dismissed.

04 · States

State changes keep their geometry

Hover, pressed, focus, selected, and disabled communicate through tone and border treatment. A control does not scale or jump to announce a state.

Hover the button or move focus with Tab.
Pressed uses #365064.
Selected uses cyan fill with dark ink.
Disabled is quiet, never hidden.
Click a mode button to inspect its selected state. Focus-visible uses a 2 px cyan inset.

Interaction contract

  • 130ms for button state changes.
  • 200ms cubic-bezier(.2,.8,.2,1) for surface motion.
  • Selected and pressed preserve dimensions and icon alignment.
  • Keyboard focus is visible; pointer focus never creates a surprise outline.
  • Reduced motion makes transitions effectively instant.
This is a command, not a toggle. It has no aria-pressed state.

05 · Timeline

A timeline needs weight

Timeline surfaces use one dark 70% alpha root, leaving 30% transparency. Inner bands use only an 8% tint over that root; labels, keys, curves and handles remain opaque and legible over the scene. Keys and Curves share the same outer editor size and preserve resize state; touch shows one editor at a time. Measure curve/effect geometry from the committed editor bounds before first paint so fallback dimensions never visibly correct. Fine-pointer desktop docks use a stable scene/editor/transport grid: opening or closing moves the editor row between zero and the saved editor height over the shared 200ms motion, while the scene and Properties cells reflow together.

Desktop docking behavior: The editor row slides up or down between 0px and the user's saved height using cubic-bezier(.2,.8,.2,1). The inner timeline keeps its full geometry and is revealed or clipped by the moving row; it does not fade, bounce or run a separate inner transition. Manual splitter drags apply immediately. A repeated or interrupted toggle reverses smoothly from its current position. Reduced motion applies the final row size instantly. Touch/coarse docking remains contextual and full-screen.

06 · Motion

Motion should explain a state

Animate a surface into its new place with restraint. The motion is a bridge, not a performance.

Context menu settles beside selected control

130ms hover, pressed, and selected state changes.

200ms cubic-bezier(.2,.8,.2,1) panel and menu movement after an explicit user action.

prefers-reduced-motion: reduce makes the disclosure immediate.
